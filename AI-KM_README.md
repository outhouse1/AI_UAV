# AI-KM Intelligent Knowledge Management Platform

## 🚀 Overview

**AI-KM (Artificial Intelligence Knowledge Management)** is a next-generation knowledge management platform integrated with cutting-edge AI technologies. Leveraging large language models and knowledge graph technology, it helps individuals and organizations achieve efficient knowledge organization, in-depth analysis, and intelligent application.
Download link: https://github.com/whl1207/Knowledge

### 🎯 Major Upgrade in Latest Version: From "Expert Tool" to "Platform for All Users"

The latest version of AI-KM represents a systematic upgrade aimed at transitioning from an "expert tool" to a "platform for all users." The core goal of this update is to reduce the operational complexity of advanced features. While maintaining deep support for professional characteristics like knowledge graphs and complex workflows, it provides a unified entry point for users with different technical backgrounds through clear module delineation and an intuitive interface design.

**Key updates include:**

### 4. 🧠 Ontology-Driven Knowledge Modeling (New!)

This module elevates knowledge representation from simple slice structures to formal, machine-interpretable ontologies. The ontology building process operates directly on existing knowledge slices, extracting entities and their relationships through a batch-based, incremental pipeline.

#### 4.1 Ontology Building Process

```
Knowledge Slices → Batch Processing → Entity Extraction → Relation Tracking → Graph Visualization → Retrieval Enhancement
```

**Key Features:**

| Feature | Description |
|:---|:---|
| **Batch-Based Extraction** | Processes slices in configurable batches with LLM-based entity/relation extraction |
| **Consistency Preservation** | Previously extracted entities serve as context for naming consistency across batches |
| **Bidirectional Linking** | Each entity records which slices contain references, linking formal ontology to unstructured content |
| **Progress Persistence** | Supports pausing and resumption of long-running ontology construction |
| **Similarity-Based Merging** | New entities merged with existing ones; associations appended, not overwritten |

#### 4.2 Ontology Visualization

Once constructed, the ontology renders as an interactive force-directed graph with distinct visual encodings:

| Node Type | Color | Edge Type | Style |
|:---|:---|:---|:---|
| Entity Nodes | Blue | Entity-Slice | Dashed Orange |
| Slice Nodes | Orange | Slice-File | Solid Brown |
| File Nodes | Brown | File-Metadata | Solid Cyan |
| Metadata Nodes | Cyan | Cross-File Reference | Dashed Gold |

**Visualization Features:**
- Toggle visibility of different node types and edge types
- Filter by metadata keys
- Search for specific nodes
- Pan, zoom, and drag operations
- Tooltips display detailed node information including descriptions and associated block previews

#### 4.3 Card View for Entity Management

The "Card View" presents entities as visual cards displaying:
- Entity name
- Description (auto-generated or user-provided)
- Association counts (number of linked slices)
- Automatic description generation from aggregated slice content
- Batch reasoning mode for efficient entity processing

#### 4.4 Ontology-Augmented Retrieval

When ontology mode is enabled during chat, the retrieval process is enhanced through entity matching:

```
User Query → Entity Matching → Score Boosting → Semantic Retrieval → Context-Augmented Response
```

**Matching Mechanism:**
1. **Direct Matching:** String matching between query and entity names
2. **LLM-Assisted Matching:** Fallback for indirect references and varied terminology
3. **Score Boosting:** Configurable multiplier applied to relevance scores of slices containing matched entities

**Value Proposition:**
- Enables semantic understanding beyond keyword matching
- Entities encapsulate domain concepts expressed through varied terminology
- Provides a formal conceptual framework organizing the underlying document collection
- Ensures consistent semantic retrieval across the entire knowledge base

### 5. 🔗 Workflow - Visual Agent Building Platform

A core breakthrough in this AI-KM update is its workflow engine, which has evolved from a task executor to a low-code agent building and orchestration platform. This engine aims to encapsulate professional Large Language Model (LLM) programming paradigms (like ReAct, planning, and tool calling) into visual, composable nodes. This allows domain experts to build, share, and deploy complex AI agent workflows without coding.

Our node design follows the principles of "modularity, atomicity, and interconnectivity." Ten types of nodes cover the core aspects of agent interaction:

#### Node Classification & Functional Description

| Category | Node Name | Core Function | Analogous Agent Capability |
| :--- | :--- | :--- | :--- |
| **Input** | Text Node | Receives text input | Perception |
| | File Node | Reads local files | Perception |
| | Web Scraping | Fetches webpage content | Perception |
| | Web Search | Searches for information online | Perception |
| **Knowledge** | Knowledge Base Node | Retrieves structured knowledge | Memory |
| | Structured Input | Processes structured data | Memory |
| **Reasoning** | Reasoning Node | Core LLM thinking/processing | Planning & Reasoning |
| **Control** | Decision Node | Conditional branching based on rules/LLM | Decision Making |
| **Execution** | Python Execution | Runs Python code | Tool Use |
| | MCP Node | Calls external tools | Tool Use |

#### 5.1 Workflow Building Experience
Workflows are built through an intuitive drag-and-drop graphical interface. Users define data flow and control flow between nodes using connecting lines. The workflow can be exported as a `.flow` file and called from the Home module.

**The key innovation lies in:**
- **Encapsulation:** Any built workflow can be saved as an independent, parameterized "skill package."
- **Reusability:** Workflow "skill packages" can be used directly in the Home conversation interface.
- **Natural Language Triggering:** Users only need to select or trigger via natural language in chat to invoke the entire complex process.

This essentially enables customized agents to function as plug-and-play conversation skills, allowing novice users to directly leverage AI capabilities built by experts.

### 6. 🤖 Agentic Skill Framework (New!)

The Agentic Skill Framework powers the Skill Mode, managing reusable AI capabilities defined by metadata and associated files. This framework transforms AI-KM from a tool users operate into an intelligent partner that can autonomously plan and execute complex tasks.

#### 6.1 Skill Definition

A skill is defined by a folder containing:

| Component | Description |
|:---|:---|
| **Metadata File** | Name, description, version, author, tags, model requirements |
| **Prompt Files** | Core instructions for the skill |
| **Configuration Files** | Parameters and settings |
| **Reference Data** | Supporting documents and examples |

The system scans the configured skills directory to load all valid skills for execution.

#### 6.2 Dual Operating Modes

| Mode | Description | Use Case |
|:---|:---|:---|
| **Explicit Skill Execution** | User request matches a loaded skill; system executes that skill's logic | Known, predefined tasks |
| **Autonomous Planning** | No skill matches or request is novel; planner dynamically generates a plan | Novel, unstructured requests |

**Intent Classification:** The system uses an LLM to distinguish between:
- Execute a specific skill
- Request help for a skill
- List available skills

#### 6.3 Planning Step Types

The autonomous planner can generate plans composed of these atomic steps:

| Step Type | Function |
|:---|:---|
| **think** | Internal reasoning and analysis |
| **web_search** | Search for information online |
| **web_fetch** | Retrieve and parse web content |
| **read_file** | Read local file content |
| **write_file** | Write content to local file |
| **run_python** | Execute Python code |
| **ask_user** | Request additional information from user |
| **replan** | Regenerate remaining steps based on user input |
| **respond** | Output final response to user |

**Planning Rules:**
- `ask_user` steps must be immediately followed by `replan` steps
- The final step must be of type `respond`
- Planning prompt includes complete execution history for context-aware adaptation

#### 6.4 Intelligent Context Compression

A critical innovation for handling large documents efficiently:

```
Large File → Threshold Check → Context-Aware Compression → Streamed Output → Preserved Integrity
```

**Compression Features:**
- **Automatic Triggering:** Activates when reading files exceeding configurable threshold
- **Context-Aware:** Compression prompt incorporates full user context including original input and conversation history
- **Adaptive Target Length:** Smaller files compress to tighter targets based on original size
- **Data Integrity:** Original content cached when write operations might need it
- **Real-Time Feedback:** Compression output streams character by character

**Example Impact:** The system can reduce original content by over 87.6% while preserving all diagnostic information relevant to specific queries.

#### 6.5 Dynamic Replanning

The execution engine supports adaptive conversation through dynamic replanning:

```
Ask User → Capture Response → Replan Step → Generate New Plan → Replace Remaining Steps
```

**Capabilities:**
- Refine approach based on new information from user
- Request additional data when needed during execution
- Adjust to changing user requirements without restarting from scratch
- Maintain execution context across replanning cycles

#### 6.6 Execution Visualization

The chat interface provides comprehensive execution visualization including:
- Execution headers with timing information
- Step-by-step progress with status icons and durations
- Streaming reasoning output
- User interaction modals for ask_user steps
- Result previews for completed steps
- Completion statistics

## 🎬 Typical Application Cases

### Case 1: Knowledge Base Processing, Retrieval, and Testing Framework

Example: Building a regulations knowledge base.

1. **Import Documents:** User saves relevant regulations in a designated folder.
2. **Automatic Processing:** System automatically performs text chunking and vectorization.
3. **Visual Optimization:** Use knowledge graph visualization tools to inspect and manually establish associations between key concepts (e.g., model names, authors).
4. **Automated Testing:** Through the automated testing framework, input a set of common questions; the system automatically evaluates retrieval results.
5. **Iterative Optimization:** Optimize chunking strategies and edit metadata tags based on test results to improve retrieval accuracy.

```
📁 Regulations → ✂️ Smart Chunking → 🔍 Vectorization → 📊 Visual Inspection → 🧪 Auto-Testing → 🔄 Iterative Optimization
```

### Case 2: Ontology Building for Course Knowledge (New!)

Example: A reliability engineering instructor formalizing course knowledge.

1. **Process Course Materials:** Upload lecture notes, case studies, and textbook excerpts to the knowledge base.
2. **Build Ontology:** Configure and initiate ontology construction; system processes batches sequentially, extracting entities and relations while maintaining naming consistency.
3. **Review and Refine:** View ontology graph showing interconnected entity nodes; use card view to examine entities with associated block counts; trigger automatic description generation for key entities.
4. **Ontology-Augmented Retrieval:** Student asks "What is the definition of reliability?" With ontology mode enabled, system matches query against entity names, identifies relevant entities, and boosts scores for associated slices.
5. **Knowledge Transfer:** Save complete knowledge base including ontology; other instructors load it with all entity definitions, descriptions, and block associations preserved.

```
📚 Course Materials → ⚙️ Ontology Construction → 🔗 Entity-Relation Graph → 🧪 Ontology-Augmented Retrieval → 🔄 Knowledge Transfer
```

### Case 3: Agentic Skill for Engine Maintenance (New!)

Example: A maintenance technician diagnosing an engine problem.

1. **Skill Selection:** User selects "Skill Mode" and enters request about engine symptoms.
2. **Skill Matching:** System analyzes input and matches it to a pre-loaded "maintenance-skill" containing diagnostic procedures and fault code reference files.
3. **Execution Planning:** Planner generates a multi-step plan including asking user for additional information, reading reference files, synthesizing symptoms with fault codes.
4. **User Interaction:** System asks what symptoms occurred; user responds "black smoke and loss of power."
5. **Context Compression:** When reading large fault code reference file, system triggers intelligent compression, reducing content by ~87.6% while preserving all diagnostic information relevant to specific symptoms.
6. **Final Diagnosis:** System outputs structured diagnosis identifying root cause, recommended actions, and estimated repair time.

```
🔧 User Request → 🎯 Skill Matching → 📋 Plan Generation → 💬 User Interaction → 📚 Compressed Reading → 📊 Structured Diagnosis
```
